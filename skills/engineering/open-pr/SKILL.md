# open-pr

Write a pull request's title and body, then create it.

## Procedure

1. Diff against the base to see what changed. The title and body describe the branch as it stands, not how it got there.
2. Title: conventional-commit form, `feat(...)` or `fix(...)`, with a concise scope and summary, such as `fix(worktree): keep worktree alive until PR merges`.
3. Link the issue when the request or branch context provides one, with a closing reference in the body such as `Fixes #123`.
   A same-repository reference closes the issue when the PR merges into the default branch; the branch name alone does not.
   Use `Fixes owner/repo#123` for another repository, and `Related to #123` when the PR should not close it.
4. Body: follow the repo's PR template when one exists, otherwise use these sections:
   - Problem / request: the problem or requested feature and what this PR does about it.
   - Changes: a short summary of what was done, grouped instead of file by file.
   - Evidence: a concise before and after. For a visual change, include before-and-after screenshots when the app can be run and captured. For other changes, show the exact test or command result, including a test that failed before and passes after. When evidence cannot be captured, state what blocked it and give the strongest verification you have. Never claim verification you did not perform.
   - Additional testing required: what a reviewer or QA should still exercise.
   - Regressions: known or potential regressions to watch for.
5. Keep it evergreen and short:
   - The body stays accurate as the branch changes and holds no volatile details such as version bumps or transient counts.
   - No AI attribution: no "generated by" note in the body and no agent co-author line in commits.
   - Aim for about 200 words and rarely exceed 400. Check with `wc -w`, because authors read their own drafts as short.
   - Cut what the diff already shows: file walkthroughs, signatures, line counts, quoted code. State each fact once. Link the spec or issue for depth.
6. Open the PR with the title and body, for example with `gh pr create`.
